# Phần UI – TV4

**Thư mục được sửa:** `web/` · **Task:** T7a, T12a, T16a (phần UI), T18 · Phần Backend của bạn: [11-backend.md](11-backend.md)

Việc của bạn: giao diện chat sinh viên dùng. UI chỉ nói chuyện với backend qua [02-api-contract.md mục 1–4](02-api-contract.md#1-post-apichat), không cần biết AI bên trong. Nhờ chế độ mock, bạn làm được ngay từ ngày đầu.

## 1. Code hiện có

HTML/CSS/JS thuần, không framework, không bước build. Backend phục vụ luôn thư mục `web/` tại <http://localhost:8000>: sửa file rồi tải lại trang (Ctrl+Shift+R) là thấy.

| File | Nội dung |
| --- | --- |
| `web/index.html` | Thanh trên (nút `#new-chat`), vùng chat `#chat` gồm màn hình trống `#empty` với 4 câu gợi ý `#suggestions` và danh sách `#messages`; ô nhập `#composer`/`#input`/`#send`; hai `<template>`: `#tpl-user`, `#tpl-bot` (bong bóng có `.status`, `.text`, danh sách `.sources`, khung `.feedback` với 2 nút `data-rating="1"`/`"-1"`) |
| `web/style.css` | Giao diện, có chế độ tối |
| `web/config.js` | `window.CHATBOT_CONFIG.API_BASE`: để `""` khi backend phục vụ web; điền URL backend khi deploy tách riêng |
| `web/app.js` | Toàn bộ logic (bảng dưới) |

Hàm trong `web/app.js`:

| Hàm | Việc |
| --- | --- |
| `getSessionId()` | Tạo/lấy `session_id` trong `localStorage["chatbot-session"]` |
| `escapeHtml(s)` | Chống chèn HTML. **Mọi chữ từ backend phải đi qua hàm này trước khi gán `innerHTML`** |
| `renderAnswer(text, msgId, sourceCount)` | Escape rồi đổi `[n]` hợp lệ thành `<a class="cite" href="#<msgId>-src-<n>">` |
| `addUser(text)`, `addBot()` | Nhân bản template, thêm vào `#messages`; `addBot` gán `id` ngẫu nhiên `m-xxxxxx` |
| `showSources(node, sources)` | Vẽ danh sách nguồn, mỗi `<li id="<msgId>-src-<n>">` |
| `showFeedback(node, answerId)` | Hiện 2 nút, bấm thì `POST /api/feedback` |
| `readSSE(response)` | Async generator đọc SSE từ `fetch` (EventSource không gửi được POST), trả `{event, data}` |
| `ask(question)` | Luồng một câu hỏi: khoá nút → `POST /api/chat` với `history.slice(-6)` → nối `token` → `sources` thì vẽ lại câu trả lời có link → `done` thì hiện feedback → lỗi thì hiện thông báo + nút "Thử lại" |

Biến toàn cục: `history` (mảng `{role, content}`, xoá khi bấm "Cuộc trò chuyện mới"), `busy` (đang chờ trả lời).

## 2. Chạy và xem dữ liệu thật

1. Chạy backend mock theo README.
2. Mở <http://localhost:8000>, F12 → tab **Network** → hỏi một câu → bấm request `chat` → tab **Response**/**EventStream**: thấy các sự kiện `token`, `sources`, `done`.
3. Tạo các trạng thái để thử, không cần sửa code backend: tắt backend rồi hỏi (lỗi mạng); đặt `MIN_SECONDS_BETWEEN_QUESTIONS=10` trong `.env`, khởi động lại, hỏi 2 câu liên tiếp (429); hỏi "công thức nấu phở bò" (mock trả `refused: true`); gửi câu > 1000 ký tự bằng `curl` (422).

## 3. Task

### T7a – Đủ trạng thái và hiển thị (tuần 2–3)

**Mục tiêu:** mỗi trạng thái có giao diện riêng rõ ràng; câu trả lời dễ đọc; dùng tốt trên điện thoại.

**Hiện trạng code:**
- Sự kiện `done` có `refused` nhưng `ask()` bỏ qua, câu từ chối trông như câu trả lời thường.
- Lỗi HTTP chỉ đọc `err.message`; lỗi 422 của FastAPI không có `message` (có `detail`) nên rơi vào nhánh mặc định — đã xử lý, giữ nguyên.
- `textEl.textContent = answer` khi đang stream; khi có `sources` thì thay bằng `renderAnswer` → mất xuống dòng vì `innerHTML` gộp khoảng trắng.
- Link `[n]` nhảy tới nguồn nhưng không làm nổi bật nguồn đó.

**Các bước:**

1. **5 trạng thái**, mỗi cái một class CSS trên `li.msg.bot`:
   | Trạng thái | Khi nào | Hiển thị |
   | --- | --- | --- |
   | `waiting` | Đã gửi, chưa có `token` | `.status` "Đang tìm văn bản liên quan…" + hiệu ứng chấm nhấp nháy |
   | `streaming` | Đang nhận `token` | Chữ chạy dần, con trỏ nhấp nháy cuối dòng |
   | `refused` | `done.refused === true` | Nền khác màu (vàng nhạt), không hiện danh sách nguồn rỗng, thêm dòng gợi ý "Bạn có thể hỏi về: đăng ký học phần, học phí, điểm, tốt nghiệp, học bổng" |
   | `error` | Lỗi mạng, `error` SSE, HTTP 5xx | Đã có class `error` + nút "Thử lại"; viết thông báo dễ hiểu ("Không kết nối được máy chủ") thay vì `Failed to fetch` |
   | `rate-limited` | HTTP 429 | Hiện `message` từ backend, nút Gửi tự mở lại sau 3 giây, không hiện nút "Thử lại" |
2. **Định dạng câu trả lời:** viết hàm `formatAnswer(text, msgId, sourceCount)` thay `renderAnswer`: escape HTML trước, rồi: dòng bắt đầu bằng `- ` hoặc `* ` → `<li>` trong `<ul>`; dòng bắt đầu bằng `1. ` → `<ol>`; `**chữ**` → `<b>`; xuống dòng → đoạn `<p>`; `[n]` → link như cũ. Không dùng thư viện markdown. Gọi hàm này cả khi đang stream (mỗi `token`) để chữ không nhảy định dạng ở cuối.
3. **Bấm `[n]`:** chặn hành vi mặc định, cuộn mượt tới `li` nguồn tương ứng, thêm class `highlight` 2 giây.
4. **Điện thoại:** DevTools → Toggle device toolbar → 375px. Ô nhập không bị bàn phím che, chữ ≥ 16px (tránh iOS tự phóng to), nút đủ lớn để bấm (≥ 40px).
5. Giữ `aria-live="polite"` trên `#chat`; nút có nhãn rõ ràng.

**Kiểm tra:** chụp màn hình 5 trạng thái (cách tạo ở mục 2) và một câu trả lời có gạch đầu dòng, cả bản desktop và 375px. Thử chèn: sửa tạm `MockGenerator` trên máy mình (không commit) cho trả `<img src=x onerror=alert(1)>` → trang phải hiện nguyên chuỗi đó, không bật alert.

**Bàn giao:** PR có ảnh chụp các trạng thái.

### T12a – Feedback và giới thiệu (tuần 4)

**Hiện trạng code:** `showFeedback` cho bấm nhiều lần, mỗi lần gửi một request; không có ô nhập lý do.

**Các bước:**

1. Bấm Đúng/Sai một lần thì khoá cả 2 nút (`disabled`), nút đã chọn có `aria-pressed="true"`.
2. Bấm "Sai": hiện ô nhập ngắn "Sai ở đâu? (không bắt buộc)" + nút Gửi; gửi `{"answer_id", "rating": -1, "comment"}`. Bấm "Đúng": gửi ngay `rating: 1`.
3. Thêm nút "Giới thiệu" trên thanh trên, mở khung (dùng `<dialog>`): phạm vi trả lời (các chủ đề ở [02-api-contract.md mục 11](02-api-contract.md#11-mã-chủ-đề-topic)), dữ liệu lấy từ đâu, lưu ý "không thay thế thông báo chính thức, luôn kiểm tra nguồn", không thu thập thông tin cá nhân.

**Kiểm tra:** bấm Sai, nhập lý do, gửi → backend có dòng mới trong `backend/logs/feedback.jsonl` (mock) hoặc bảng `feedback` (Supabase) với đúng `comment`. Bấm lại không gửi thêm.

### T16a – Deploy (phần UI, tuần 7)

Cách đơn giản nhất: để backend phục vụ luôn `web/` (không phải làm gì thêm). Nếu tách UI ra host tĩnh (GitHub Pages, Netlify, Vercel):

1. Sửa `web/config.js`: `API_BASE: "https://<địa-chỉ-backend>"` (không có `/` ở cuối).
2. Thêm domain của UI vào `CORS_ORIGINS` của backend ([11-backend.md, T16a](11-backend.md#t16a--mở-công-khai-tuần-7)).
3. Kiểm tra trên điện thoại thật qua 4G (không phải Wi-Fi nhà).

### T18 – Kịch bản demo (tuần 8)

Cùng Khiêm chuẩn bị 5–7 câu: 1 dễ, 2 khó (nhiều điều kiện), 1 hỏi tiếp theo ngữ cảnh, 1 ngoài phạm vi (phải từ chối), 1 câu so sánh trực tiếp với HustVA. Chạy thử trước buổi demo trên đúng bản deploy, chụp màn hình dự phòng khi mạng lỗi.

## 4. Lỗi thường gặp

| Hiện tượng | Nguyên nhân hay gặp |
| --- | --- |
| Bấm gửi không có gì, Console báo CORS | Mở `index.html` bằng `file://`. Mở qua <http://localhost:8000> |
| Sửa `app.js` mà trang không đổi | Trình duyệt cache; Ctrl+Shift+R |
| Chữ hiện cả cụm một lúc, không chạy dần | Proxy/host gom response; backend đã đặt `X-Accel-Buffering: no`, kiểm tra cấu hình host |
| Báo 429 liên tục | Đặt `MIN_SECONDS_BETWEEN_QUESTIONS=0` trong `.env` khi test, khởi động lại backend |
| Chèn câu trả lời làm vỡ giao diện | Quên `escapeHtml` trước khi gán `innerHTML` |
